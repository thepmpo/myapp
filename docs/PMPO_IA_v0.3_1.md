# PMPO IA (정보구조) v0.3 — 명칭 변경 반영본

> v0.2 확정본에서 메뉴 명칭을 변경하고, 사이드바 구조(카테고리 노출 방식)를 수정한 버전입니다.
> 변경 배경은 문서 맨 아래 "6. 명칭 변경 및 사이드바 구조 변경" 섹션 참고.

---

## 1. 전체 사이트맵

```
홈 (랜딩)
├── Insights (관리자 발행 아티클) — 사이드바 1depth
│   ├── Product — 사이드바 2depth (상시 노출)
│   │   ├── 아티클 목록
│   │   └── 아티클 상세
│   ├── Trends — 사이드바 2depth (상시 노출)
│   │   ├── 아티클 목록
│   │   └── 아티클 상세
│   └── AI — 사이드바 2depth (상시 노출)
│       ├── 아티클 목록
│       └── 아티클 상세
├── Circle (질문/답변, 단일 피드) — 사이드바 1depth
│   ├── 게시글 목록 (정렬/필터: 최신순, 답변 없는 질문만 보기)
│   │   └── 게시글 상세 (댓글, 좋아요)
│   └── 질문 글쓰기
├── 마이페이지 (로그인 시)
│   ├── 프로필 (뱃지, 팔로우 수)
│   └── 내 정보 수정
└── 로그인 / 회원가입
    ├── 로그인
    ├── 회원가입 (약관 동의 포함)
    ├── 비밀번호 재설정
    └── 로그아웃
```

### 설계 결정 및 근거

- **Insights vs Circle 분리**: Insights는 관리자만 발행(PRD Must-have 2), Circle은 유저의 질문 중심(Must-have 1)이라 목적이 다름. 각 화면에 다른 기능이 붙기 때문에 메뉴 단계에서부터 분리.
- **Insights = 카테고리 3분류(Product/Trends/AI)**: 콘텐츠 소비 목적이 뚜렷해 초기부터 분류가 유효하다고 판단.
- **Circle = 카테고리 없이 단일 피드**: 초기엔 자유로운 질문/소통이 우선. 카테고리를 미리 강제하면 글쓰기 진입장벽이 생길 수 있어 데이터가 쌓인 뒤 재검토(백로그).
- **"라이브러리(북마크/모아보기)" 메뉴는 제외**: PRD Out of Scope 1번과 목적이 겹쳐 백로그로 이동.

## 2. 로그인 필요 여부

| 페이지/액션 | 비로그인 | 로그인 필요 |
|---|---|---|
| Insights 목록/상세 보기 | ✅ | - |
| Circle 게시글 목록 보기 | ✅ | - |
| **Circle 게시글 상세 보기** | **❌ (v0.4에서 변경)** | **✅** |
| 질문 글쓰기 | ❌ | ✅ |
| 댓글(답변) 작성 | ❌ | ✅ |
| 좋아요 누르기 | ❌ | ✅ |
| 팔로우 | ❌ | ✅ |
| 마이페이지 | ❌ | ✅ |

**설계 근거 (v0.4 변경)**: 원래는 "읽기는 비로그인 허용(트래픽 확보), 쓰기만 로그인 필요" 원칙이었으나, Circle 상세 진입은 "쓰기"가 아님에도 로그인 장벽을 두는 것으로 변경. 근거: 목록을 훑어보는 것보다 특정 글을 클릭해 상세로 들어가는 행동이 더 강한 관심 신호이므로, 이 지점에서 로그인을 요구해도 이탈보다 가입 전환이 클 것으로 판단. 또한 가입 허들이 전혀 없으면 실제 가입자 확보가 어렵다는 문제의식도 반영. Insights는 이 변경 대상에서 제외 (관리자 발행 콘텐츠라 트래픽 확보 목적이 더 크다고 판단, 필요 시 재검토).

## 3. 페르소나별 유저 플로우

```
[주니어 PM]
홈 → Circle 둘러보기/검색 → [원하는 답 있음] → 게시글 상세 확인 → 종료
                          → [원하는 답 없음] → 로그인 → 질문 글쓰기 → 답변 대기

[PM 취업 희망자]
홈 → Insights (Trends 카테고리 확인) → Circle 검색 (취업 관련 질문)
   → [질문 없음] → 로그인 → 질문 글쓰기
   → [질문 있음] → 게시글 상세 확인 → 로그인 → 댓글로 추가 질문 → 답변 대기

[시니어 PM]
홈 → Insights (딥한 정보 확인) → Circle (답변 없는 질문 필터로 확인)
   → 로그인 → 답변 작성 → 좋아요/팔로우 획득
```

## 4. 백로그 (지금은 안 함, 기록만 해둠)

1. **라이브러리(북마크/모아보기) 메뉴** — PRD Out of Scope와 목적 중복
2. **Circle 카테고리 분류** — 질문 수가 쌓인 뒤 실제 데이터 기반으로 재검토
3. **Insights 내 롱폼/심층 콘텐츠 섹션 분리** — 도입 시 "Reads"를 섹션명 후보로 재검토 (명칭 논의 시 남겨둔 후보)

## 5. 게시판 표현 형식

## 6. 명칭 변경 및 사이드바 구조 변경 (v0.3, 신규)

### 명칭 변경

| 기존 | 변경 | 이유 |
|---|---|---|
| 커뮤니티 | **Circle** | "커뮤니티"가 범용적이고 서비스 개성이 드러나지 않는다는 판단. Circle은 "함께 모여 묻고 답한다"는 의미를 담고, 향후 뱃지 체계("Inner Circle" 등)로 브랜드 확장 가능 |
| 정보게시판 | **Insights** | "게시판"이라는 표현이 구식(PC통신/카페) 느낌을 줌. 에디토리얼 매거진 톤(Asterisk, Works in Progress 레퍼런스)과도 더 잘 맞음 |
| 프로덕트 | **Product** | 카테고리명 전체를 영문화 |
| PM/PO 트렌드 | **Trends** | 카테고리명 전체를 영문화 |

**주의**: Circle은 영어 단어라 의미가 바로 와닿지 않을 수 있어, Circle 게시글 목록 페이지 상단(제목 아래)에 짧은 설명 카피를 넣기로 함 (톤앤보이스 v0.2 참고). Insights/Product/Trends/AI에는 별도 설명 카피 불필요 (의미가 비교적 명확함).

### 사이드바 구조 변경

- **기존(v0.7 화면설계 기준)**: Insights 진입 후 페이지 내부 탭(Product/Trends/AI)으로 카테고리 전환
- **변경**: 좌측 사이드바에 Circle, Insights를 동일한 시각적 비중의 1depth 메뉴로 배치. Insights 아래에 Product/Trends/AI를 들여쓰기된 2depth 메뉴로 **펼치기/접기 없이 항상 노출** (아코디언 아님 — Medium의 "Following" 리스트처럼 상시 노출 방식)
- **URL 구조**: 카테고리별 고유 URL 필요 — `/insights/product`, `/insights/trend`, `/insights/ai`. 직접 링크 공유, 브라우저 뒤로가기, 사이드바 active 상태 표시가 모두 이 구조에 의존하므로 필수
- **Insights 클릭 시 기본 동작**: 카테고리 없이 "Insights"만 클릭하면 기본 카테고리(Product)로 이동
- **active 상태 표시**: 배경색이 아니라 왼쪽 2px 액센트 라인 + 볼드 텍스트 (컬러 시스템 v1.1 원칙 — 배경 채우는 칩 대신 라인/텍스트로만 상태 표시)

## 6. 사이드바 구조 재변경 (v0.4, 신규 — 최신)

> 아래 내용이 5번 섹션(Insights 1depth + 카테고리 2depth 상시 노출)을 **대체**합니다.

### 변경 사항

- **"Insights" 상위 메뉴 제거.** Product/Trends/AI를 Insights 하위(2depth)가 아니라 **Circle과 동급인 1depth**로 사이드바에 바로 노출.
- **근거**: 처음 방문한 유저가 사이드바만 보고도 "이 사이트에 뭐가 있는지" 한눈에 파악하는 게 목적. 2depth 구조면 Insights를 먼저 클릭해야 하위 카테고리를 볼 수 있어, 존재 자체를 인식 못 하거나 진입 자체를 안 할 위험이 있다고 판단.
- **최종 사이드바 1depth 구성**: Circle / Product / Trends / AI (4개, 동급)
- **URL 구조는 변경 없음**: `/insights/product`, `/insights/trend`, `/insights/ai` 그대로 유지 (내부 라우트/데이터 그룹핑 개념으로는 Insights가 남아있지만, UI 메뉴 라벨로는 노출 안 함)
- **선택 상태 디자인 변경**: 기존엔 "1depth는 색 없이 볼드만, 2depth만 accent 라인+색"이었으나, 이제 전부 동급 1depth가 되면서 이 구분이 무의미해짐. 새 원칙: 선택된 메뉴는 왼쪽 2px accent 라인 + 볼드 텍스트에 더해, **연한 무채색(회색) 배경을 살짝 깔아 선택 무게감을 보강**. 배경색 자체는 계속 무채색이라 컬러 시스템 v1.1의 "액센트는 꼭 필요한 곳에만" 원칙은 유지됨.
- **모바일 영향**: 하단 탭바의 "Insights" 탭에서 Product/Trends/AI를 고르던 드롭업 패널 구조도 이 변경에 맞춰 재검토 필요 — 하단 탭바에 Circle/Product/Trends/AI/마이페이지가 다 들어가면 탭이 5개라 개수가 늘어남. 별도 확인 필요 (아래 "확인 필요" 참고).

## 7. 프로필 위치 변경 (v0.4, 신규)

- **사이드바 최하단 프로필 영역 완전히 제거.**
- **프로필은 우측 상단 헤더로 이동.**
- **근거**: 사이드바 메뉴 개수가 늘어나면(6번 변경으로 4개가 됨) 하단 프로필까지 스크롤해야 하는 문제가 생길 수 있음. 우측 상단 고정 위치가 더 빠르게 찾고 이동하기 좋다고 판단.
- **모바일 영향**: 모바일 하단 탭바의 "마이페이지" 탭은 이 변경과 무관하게 유지 (데스크톱 사이드바에만 해당하는 변경).
- **확인 필요**: 데스크톱에 "우측 상단 헤더"라는 개념 자체가 화면설계 문서에 명확히 정의된 적이 없어, 헤더에 뭐가 같이 들어가는지(로고 위치, 검색 등) 별도로 정리 필요.
