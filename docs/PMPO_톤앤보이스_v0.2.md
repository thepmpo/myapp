# PMPO 톤앤보이스 가이드 v0.2

> UI 카피, 안내 문구, 에러 메시지 등 서비스 전체의 "말투"를 일관되게 유지하기 위한 기준 문서입니다.
> v0.1에서 명칭 변경(커뮤니티→Circle, 정보게시판→Insights)에 따른 신규 카피를 추가했습니다.

## 한 문장으로

**"전문성은 있지만 어깨에 힘 안 준 선배가 말해주는 느낌."**

PM/PO라는 전문 직군 대상 서비스지만, 격식 있는 업무 문서 톤이 아니라 동료끼리 편하게 묻고 답하는 톤을 씁니다.

## 원칙 4가지

1. **명령하지 않고 권한다** — "~하세요" 대신 "~해보세요", "~하시겠어요?" 같은 부드러운 어미
2. **어려운 말을 쉽게 풀어쓴다** — 기술 용어(RLS, API 등)를 사용자 대상 카피에는 노출하지 않음. 내부 문서(PRD 등)에서는 정확한 용어 사용, 유저가 보는 화면에서는 쉬운 말로 번역
3. **실패도 친절하게** — 에러 메시지는 탓하지 않고, 다음에 뭘 하면 되는지 알려줌
4. **짧게 말한다** — 한 화면에서 한 번에 너무 많은 정보를 설명하지 않음. 꼭 필요한 말만

## 이미 정해진 표현들 (재사용)

| 상황 | 문구 |
|---|---|
| 질문 태그 | 🙋 질문있어요 |
| 사이드바 글쓰기 유도 | 궁금한 게 있으신가요? |
| 댓글 빈 상태 | 아직 답변이 없어요. 첫 답변을 남겨보세요 |
| 게시글 빈 상태 | 아직 게시글이 없어요. 첫 질문을 남겨보세요 |
| 비로그인 댓글창 | 로그인 후 답변을 남길 수 있습니다 |
| **Circle 소개 카피** *(v0.2 신규)* | **질문하고 답하며 함께 성장하는 자리예요** — Circle 게시글 목록 페이지 상단, 제목 아래 서브텍스트로 노출 |

> Circle 소개 카피 관련 참고: "Circle"은 영어 단어라 처음 보는 유저는 의미를 바로 이해하기 어려울 수 있어, 목록 페이지 진입 시 한 번은 꼭 보이도록 상단에 고정 노출합니다 (툴팁처럼 놓치기 쉬운 위치는 지양).

## Do / Don't

| Do | Don't |
|---|---|
| "질문을 올리면 답변자들이 확인해요" | "질문 등록 시 답변자에게 알림이 발송됩니다" |
| "아직 팔로워가 없어요" | "팔로워 데이터가 존재하지 않습니다" |
| "잠깐, 확인이 필요해요" (경고) | "오류: 필수 값 누락" |
| 물음표로 끝나는 부드러운 유도 ("궁금한 게 있으신가요?") | 명령형 CTA만 나열 ("질문 등록") |

## 예외 — 이 톤을 안 쓰는 곳

- **법률 문서(이용약관, 개인정보처리방침)**: 여기는 격식 있는 문서체 유지. 톤앤보이스보다 법적 정확성이 우선
- **에러 로그, 관리자 페이지**: 내부용 화면은 실무자 대상이라 좀 더 건조하고 정확한 정보 전달 우선

## 명칭 관련 원칙 (v0.2 신규)

- 메뉴/섹션명("Circle", "Insights", "Product", "Trends", "AI")은 영문을 그대로 사용하고, 한글로 음차 표기(써클, 인사이트 등)하지 않습니다.
- Circle처럼 의미가 직관적이지 않은 명칭은 반드시 진입 지점에 짧은 설명 카피를 둡니다. Insights/Product/Trends/AI는 의미가 비교적 명확해 별도 설명 카피 없이 사용합니다.

## 앞으로 새 문구 쓸 때 체크리스트

1. 명령형 대신 권유형으로 썼는가
2. 전문 용어를 유저가 이해할 말로 바꿨는가
3. 에러/빈 상태 문구에 "다음에 뭘 하면 되는지" 있는가
4. 한 문장이 너무 길지 않은가
5. *(신규)* 영문 명칭을 쓴다면, 의미가 직관적이지 않은 경우 설명 카피가 함께 있는가
