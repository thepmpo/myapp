# PMPO PRD v0.5

## 배경 (Background)

트렌드, 데이터, 업무 방식, 생산성 등 PM 관련 정보를 얻으려고 여기저기 사이트를 돌아다니며 서칭해야 하고, 진행 중인 프로젝트/프로덕트에 대한 정보를 공유하거나 공유받을 수 있는 곳을 찾기 어려움. 국내에서 많이 쓰는 슬랙, X, 카카오톡 채널, 브런치, 텔레그램, 밴드, 스레드 등이 있지만 관련 정보를 찾기 어렵고 폐쇄성이 짙은 채널이 많음. PM/PO 전문 플랫폼이 아니다 보니 신뢰성도 떨어짐. 전문적인 커뮤니티·정보 채널이 없다 보니 이런 문제가 발생함.

이를 검증하기 위해 PMPO 관련 정보를 요약 정리해 주는 카카오톡 채널을 만들어 초기 유입자 100명을 모집하여 운영하였고, 6개월 이상 이탈률 10% 내외로 유지됨. 그리고 해당 채팅방에서 현직 주니어 PM이나 PM 취업희망자가 카카오톡 채팅으로 질문이 있었으나 답변이 없었음.

## 문제 정의 (Problem)

PM/PO 직종자, 취업 희망자 등이 프로덕트 관련 정보나 트렌드, 프로덕트에 활용되는 AI 관련 정보를 얻을 수 있고, 커뮤니티로 서로 소통하며 의견을 나누거나 해답을 얻을 수 있는 전문 PMPO 서비스가 없음. 또 자신이 필요한 프로덕트 관련 질문에 대한 답변을 받을 수 없음.

> **설계 결정**: 여기서 "질문"은 격식 있는 Q&A(선생님-제자 구조)가 아니라, 가볍게 묻고 답하는 대화 전반을 포함하는 개념으로 정의함. 이에 따라 커뮤니티는 별도의 "Q&A 게시판"이 아니라 자유로운 대화형 단일 피드로 설계함 (IA v0.2와 일치).

## 타겟 유저 (Target User)

1. 주니어 PM(1-5년차) — 본인 프로덕트에 맞는 정보 요구 수요자
2. PM 취업 희망자 — 기업 및 PM 트렌드 정보 수요자
3. 시니어 PM(6년차) — PM 트렌드 및 AI 관련 정보 수요자

## 목표 (Goal)

1. 유저가 얻는 것: 다양한 정보 / 커뮤니티를 통한 소통
2. 관리자가 얻는 것: 트래픽 / 이후 유료 자료

## 왜 이 솔루션인가 (Alternatives Considered)

1. PMPO 전문 플랫폼이 없음. '데이터리안'처럼 한 분야를 전문으로 하는 서비스는 그만큼 정보·소통에 필터링이 있어 더 명확하게 인식되고 이용하기 편함.
2. 카카오톡 그룹채팅은 초대받거나 초대 링크가 있는 사람만 참여 가능해 폐쇄적임. 누구나 쉽게 접근 가능한 플랫폼이 필요함.

## 핵심 유저 시나리오 (Core User Flow)

1. **주니어 PM** — 본인 프로덕트에서 가진 문제를 해결하기 위해 게시글에서 찾아보며, 못 찾을 경우 커뮤니티에서 검색해 본다.
2. **PM 취업 희망자** — 자소서에 쓰거나 산업 트렌드를 보기 위해 게시글을 확인하며, 커뮤니티에 취업 관련 질문을 물어본다.
3. **시니어 PM** — PM 관련 딥한 정보나 AI/트렌드 정보를 얻기 위해 게시글을 확인하고, 이후 어떤 질문·관심사가 있는지 궁금해서 커뮤니티 답변을 확인하러 방문하고, 가능하면 답변한다.

## 핵심 기능 목록 (Must-have)

1. 커뮤니티에 궁금한 게시글을 올리고 댓글로 소통하는 커뮤니티
   - 게시글 작성 시 **"질문있어요" 태그 선택 가능 (선택사항)**
2. PMPO 관련 글을 올리는 기능 (관리자 관점)
   - **작성은 관리자만 가능하지만, 좋아요/댓글은 커뮤니티와 동일 규칙으로 유저에게 허용** (1depth, 대댓글/공유 없음)
3. 우수 답변 및 팔로우 수에 대한 보상/인정 장치
   1. 답변에 좋아요 기능
   2. 팔로우 수에 따른 뱃지 삽입 기능 — **작성자 프로필/닉네임 클릭 시 팔로우 가능**
4. 커뮤니티 게시글 목록 정렬/필터에 **"'질문' 태그된 글 중 댓글 없는 것만 보기"** 옵션 추가
5. **게시글에 이미지 첨부 기능 (선택)** — Supabase Storage 기반. 목록에서는 이미지 있는 글은 썸네일 우선 노출

## 제외 범위 (Out of Scope)

1. 프로필에서 게시글을 보거나 모아볼 수 있는 기능
2. 시니어나 인지도 있는 PMPO가 작성하는 글의 유료 구독 기능
3. 기업과 연차가 확인될 경우 인증 PM 문구 삽입
4. **댓글에 대한 대댓글(스레드형 답글) 기능** — 초기엔 단일 뎁스 댓글만 지원, 답글이 필요하면 새 댓글로 작성
5. **게시글/댓글 공유 기능**
6. (4번 부가) 대댓글이 없으므로, 댓글 단위의 좋아요/댓글/공유 기능도 자동 제외

## 성공 지표 (Success Metric)

1. **"질문" 태그된 게시글** 중 답변(댓글)이 1개 이상이라도 달린 비율 80% 이상
2. 첫 질문 후 답변(댓글)이 달리는 시간 2시간 이내
3. (보조지표) 정보 게시글 업로드 후 1주일 안에 3천뷰 이상

## 제약 조건 (Constraints)

1. 예산의 부족
2. 개발 지식 없음
3. PM 실무 능력(중) — 실무적으로 디테일 부족
4. 출시 전 필요 사항: 이용약관, 개인정보처리방침, 회원가입 동의 UI 등

## 오픈 질문 (Open Questions)

1. 게시글을 어떻게 하면 좋을지 고민 → **해소**: Medium 스타일 리스트형 게시판으로 확정 (IA v0.2)
2. 수익화를 어떻게 하면 좋을지 고민 — 유료 뉴스레터 방향은 아직 방향성 부족, 계속 열어둠
3. **(신규)** "질문" 태그 없이 올라온 순수 정보공유 글도 댓글이 안 달리면 "미답변"으로 잡혀 성공지표(80%)를 왜곡할 가능성 — 화면설계 단계에서 필요시 보완 검토

## 리스크 및 대응 (Risks & Mitigations)

1. 유저의 신고 기능
2. 관리자의 유저 게시글 및 댓글 작성 블락 기능
3. 키워드 확인 후 차단 기능
4. 무성의하거나 지속적인 홍보, 자극적 언어 행동 → 추후 고민

## 백로그 (이후 버전에서 고려)

1. 댓글 공유 기능
2. 대댓글(스레드) 기능
3. 커뮤니티 카테고리 분류 (질문 수 쌓인 뒤 재검토)
4. 라이브러리(북마크/모아보기) 메뉴
5. **게시글 영상 직접 업로드** — 초기엔 미지원. 스토리지 비용·스트리밍 처리 부담으로 예산/개발지식 제약과 충돌. 필요시 유튜브 등 외부 링크 임베드로 우회 검토
