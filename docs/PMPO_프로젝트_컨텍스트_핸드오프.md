# PMPO 프로젝트 컨텍스트 핸드오프

> 이 문서는 기획 대화(ChatGPT)와 코딩 대화(ChatGPT)를 검토해서 정리한 요약본입니다.
> Claude Code로 넘어갈 때 이 파일을 프로젝트 폴더의 `docs/` 안에 넣어두면,
> 새 세션에서도 이 내용을 그대로 읽고 이어받을 수 있습니다.

## 1. 프로젝트 배경

- PM/PO들이 자신의 상황에 맞는 정보·문제 해결 답을 얻기 어렵다는 문제의식에서 시작
- 카카오톡 오픈채팅방에서 6개월간 정보 큐레이션을 직접 운영, 100명 이상 이탈 없이 유지 → "정보 큐레이션 수요"는 검증됨
- 이후 발견한 더 날카로운 문제: **"질문은 있지만 답변이 잘 생성되지 않는 구조"**
  - 원인: 답변에 대한 보상 없음 / 답변 부담(귀찮음, 평가 리스크) / 일반화된 정보라 자기 상황에 적용 어려움

## 2. 현재 문제 정의 (최신 버전)

> "PM은 자신이 처한 상황(Context)에 맞는 경험 기반 문제 해결 답을 얻기 어렵고,
> 커뮤니티 안에서도 답변이 자연스럽게 생성되지 않는다."

## 3. 기술 스택 (이미 구축됨)

- 프론트엔드: Next.js (React, TypeScript)
- 백엔드/DB: Supabase (PostgreSQL, Auth)
- 배포: Vercel (GitHub 연동, push 시 자동 배포)
- 개발 환경: Cursor

## 4. 현재 구현 상태

- `posts` 테이블 기준 CRUD 구현됨
- Vercel에 배포된 상태 (myapp-taupe-seven.vercel.app — 실제 도메인은 프로젝트 확인 후 갱신 필요)
- **막혀 있는 지점**: Supabase Auth 로그인 연동 중, `author`(문자열) 비교 방식을 실제 `user.id === post.user_id` 비교로 바꿔야 하는 단계에서 중단됨 (2026-04-07 기준, 이후 진행 없음)

## 6. 작업 방식 원칙

- 개발 지식 없는 상태로 진행 중 → 기술 용어보다 제품 관점으로 설명받는 것을 선호
- 기획 문서와 코드가 한 곳(리포지토리)에 함께 있는 구조를 선호
- 폭넓은 리서치가 필요한 경우(경쟁사 UX 비교 등)는 별도로 명시적으로 안내받기를 원함
