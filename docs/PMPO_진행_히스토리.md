## 1단계 — 문제 검증 (기획 이전)

- PM/PO 관련 정보를 요약해주는 카카오톡 채널을 6개월간 직접 운영 (초기 100명, 이탈률 10% 내외 유지)
- 이 과정에서 "정보가 없어서"가 아니라 **"질문은 올라오는데 답변이 안 달리는 문제"**를 실제로 관찰
- 이 관찰이 PMPO 전체 프로젝트의 출발점이 됨

## 2단계 — PRD (여러 라운드에 걸쳐 확정)

- 초안은 "정보 부족"이라는 얕은 문제정의로 시작했다가, 카톡방 검증 데이터를 근거로 **"답변 생성 문제"**로 다시 세움
- 핵심 논쟁: "질문"을 격식 있는 Q&A로 볼지, 가벼운 대화로 볼지 → **가벼운 대화형**으로 확정, 이후 IA/디자인 전체에 영향
- Must-have 기능을 여러 차례 다듬음: 질문 태그 → 미답변 필터 → 좋아요/팔로우/뱃지 → 이미지 첨부까지 순차적으로 추가
- 성공지표를 "글/댓글 개수"(vanity metric)에서 "답변률 80%, 응답시간 2시간"(행동 지표)으로 교정
- 법적 체크리스트(약관, 개인정보처리방침) 반영

## 3단계 — IA (정보구조)

- 정보게시판(관리자 발행) vs 커뮤니티(유저 질문) 분리 결정, 단 소비 방식은 동일 규칙 공유
- 로그인 기준: 읽기는 비로그인 허용(트래픽 확보), 쓰기만 로그인 필요
- 사이트맵 depth 표기 오류 등 실무 디테일 짚으며 확정

## 4단계 — 화면설계 (와이어프레임)

- 총 10개 화면 설계, 저해상도 이미지로 실제 산출물화
- 진행 중 발견된 이슈들: 인기 댓글 판단 기준 정의, 조회수 중복 집계 정책, 회원 탈퇴 시 데이터 처리 정책(닉네임 유지·프로필사진 리셋·글은 유지) 등을 그때그때 결정하며 문서화
- 데스크톱 레이아웃은 별도로 반응형 규칙 정립 (좌측 고정 내비, 콘텐츠형 vs 폼형 화면 구분)

## 5단계 — UI 디자인

- 컬러(코발트/앰버/세이지), 타이포그래피, "질문있어요" 포스트잇 태그라는 시그니처 요소 확정
- 초기 폰트(Space Grotesk 등)는 실제 배포 환경에서 로드 안 되는 문제 발견 → Noto Sans CJK KR로 교체
- 아이콘도 이모지 대신 SVG로 교체, 카드에 그림자 추가해서 "원초적으로 보인다"는 피드백 개선

## 6단계 — 개발 (Claude Code)

- 기존에 막혀있던 Supabase Auth 로그인(매직링크 → 이메일+비밀번호로 전환) 문제부터 해결
- PRD Must-have 기능 순차 구현: 질문태그 → 댓글 → 좋아요 → 팔로우+뱃지 → 이미지 첨부
- RLS 보안 정책 전체 테이블 적용, 자기 자신을 관리자로 바꿀 수 있는 보안 구멍 발견 후 즉시 수정
- 정보게시판(카테고리 탭, 관리자 발행 + 유저 좋아요/댓글) 구현
- 법률 문구 초안 작성 (검토 필요 표시 유지)
- 공용 내비게이션(Sidebar/AppShell) + 실제 디자인 시스템을 전체 페이지에 적용

## 트러블슈팅 기록 (실제로 겪었던 사고들)

- **로그인 방식 불일치**: 화면설계는 이메일+비밀번호였는데 코드는 매직링크로 구현되어 있던 것 발견 → 통일
- **작성자 정보 오류**: 로그인 여부와 무관하게 아무나 글 작성 가능했던 버그, 작성자가 항상 고정값("test@test.com")으로 기록되던 문제 → 실제 로그인 유저 정보로 수정
- **사이드바 사고**: Cursor 명령어 팔레트를 실행하려다 AI 에이전트 채팅창에 텍스트가 잘못 입력되어, 요청하지 않은 코드 변경(+3600줄)이 발생 → git 되돌리기로 복구, 이 과정에서 처음으로 `git push`를 하게 되어 오히려 로컬에만 있던 작업들이 GitHub에 백업되는 계기가 됨
- **iCloud 이동 중 "폴더 삭제" 오탐**: 작업 폴더를 iCloud Drive로 옮기는 과정에서 Claude Code가 예전 경로를 계속 보고 있어 "폴더가 사라졌다"고 오판 → 실제로는 안전하게 이동된 상태였음, 새 세션으로 정상 복구
- **도메인 연결**: 아임웹에서 구매한 도메인을 Vercel에 연결하는 과정에서 아임웹의 A레코드 제한 정책(2021년부터 보안상 차단)에 부딪힘 → 아임웹 상담원을 통한 네임서버 자체 이전으로 해결, DNS 전파 대기 중

## 지금까지 배운 것 (다음 프로젝트에 재사용 가능)

- PRD/IA/화면설계/디자인 각 단계에서 "왜 이렇게 결정했는지" 근거를 남기는 습관이 실제로 트러블슈팅 속도를 높여줌 (문제 생겼을 때 원래 의도를 바로 찾을 수 있었음)
- 기기를 바꿔가며 작업할 땐 "떠나기 전 push, 도착해서 pull" 습관이 핵심
- AI 에이전트에게 새 기능을 요청할 때, 범위 밖 아이디어(예: 인기 게시글 사이드바)가 자연스럽게 튀어나오는데, 이걸 바로 반영하지 않고 "새 기능이니 확인 필요"로 구분하는 습관이 스코프 관리에 중요했음
